# 实际验证

1. 用标注尺寸核对模型坐标；区分尺寸链、墙中线和墙面。把原图叠加到 2D 模型，查看外轮廓、内墙、门窗与阳台，发现偏差先修数据。
2. 检查房间相邻关系、门洞落点、家具是否挡门；每个 `view.at` 应落在房间里，视线不要卡在柜内。
3. 在本地文件模式打开构建结果，禁用网络。检查 WebGL 实际绘制和脚本错误；拖动环顾与移动、升降、房间飞入、2D/3D 返回、底图、透视和昼夜开关各验证一次。
4. 截图查看桌面与窄屏；手机按钮应可点击，面板不能遮住全部模型。夜景确保房间仍可辨认，透视开关恢复后墙材质与遮挡正常。
5. 构建另一份不同尺寸/房间数的虚构数据，确认没有把当前用户的户型写死。对无效坐标、负尺寸、洞口越界至少做一次拒绝检查。
6. 若要上传 Skill：保留 Three.js 的 MIT 许可，检查第三方说明，扫描文件中的私密图像、个人绝对路径和密钥。只上传通用模板、脚本和虚构示例；按用户指定的仓库权限发布。

可选自动化（不新增安装）：

```text
node scripts/check.mjs <交付.html> --playwright <现有playwright模块目录> --browser <现有Chrome或Edge可执行文件>
```

检查脚本会实际渲染并输出截图与 JSON，错误时返回非零状态。它不证明尺寸符合原图，也不计算结构安全、照度或施工可行性。
